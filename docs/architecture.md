# PhishScope + Sigma Detection Toolkit Architecture

This document captures the current architecture and major design boundaries for PhishScope.

## Component A: PhishScope Analysis Pipeline
PhishScope operates via a strict sequential pipeline to ensure offline-first safety and separation of concerns.

`EmailParser` → `HeaderAnalyzer` → `ExtractorAnalyzer` → `AuthAnalyzer` → `ScoringEngine` → `CLI Reporter`

### 1. Parsing (`EmailParser`)
- Leverages the standard library's `email.policy.default` to extract structured representations safely.
- Separates routing, authentication, and content without executing attachments or arbitrary decodings.
- Sanitizes filenames (preventing `../` traversal) and enforces limits (25MB size, 50 MIME part depth) to prevent resource exhaustion/ReDoS.

### 2. Header Security Analysis (`HeaderAnalyzer`)
- Evaluates structural parser outputs for potentially suspicious characteristics (heuristics).
- Identifies From/Reply-To mismatches, display-name spoofing against freemail domains, lookalike/punycode domains, and urgency language.

### 3. Extraction & Body Analysis (`ExtractorAnalyzer`)
- Parses plaintext and HTML bodies to safely extract URLs.
- Identifies IP-based URL hostnames.
- Extracts attachment metadata (hashes, MIME types) without executing files.

### 4. Static Authentication Analysis (`AuthAnalyzer`)
- Parses `Authentication-Results` and `Received-SPF` headers entirely offline.
- Handles folded, multiline, duplicated, and malformed headers safely.
- Note: This is static evidence. PhishScope does not perform live DNS checks (SPF/DKIM/DMARC resolution) to validate authenticity.

### 5. Scoring (`ScoringEngine`)
- Aggregates the standard `Finding` objects generated by the preceding analyzers.
- Calculates a final deterministic heuristic risk score (0-100) and an assessment confidence.
- Utilizes category saturation limits (diminishing returns) and strict cross-category rules for `CRITICAL` escalation.
- **Findings are heuristic evidence, not proof of maliciousness**, and scoring does not represent a strict probability.
